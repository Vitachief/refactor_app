# Analysis — Рефакторинг парсера логов

Проект представляет собой библиотеку и CLI-утилиту для парсинга, фильтрации и анализа структурированных логов. В ходе работы был проведён глубокий рефакторинг исходного кода для устранения 11 антипаттернов, улучшения идиоматичности Rust-кода и исправления скрытых логических ошибок.

## Выполненные требования (11 пунктов ТЗ)

| № | Антипаттерн | Что было сделано |
|---|---|---|
| 1 | **Лишние `clone()` вместо ссылок** | Сигнатура трейта `Parser` изменена на работу со срезами `&'a str` вместо `String`. Все комбинаторы теперь возвращают остаток строки без аллокаций (zero-copy parsing). |
| 2 | **`Rc<RefCell<T>>` там, где можно обойтись ссылками** | Функция `read_log` и итератор `LogIterator` теперь используют дженерики (`R: std::io::Read` / `R: std::io::BufRead`), что устраняет накладные расходы на подсчёт ссылок и динамическую диспетчеризацию. |
| 3 | **Циклы вместо итераторов** | Фильтрация логов переписана с использованием цепочек `.filter().collect()`, что делает код декларативным. |
| 4 | **`unsafe` без необходимости** | Удалены `RefMutWrapper` и `std::mem::transmute`, которые использовались для обхода ограничений времени жизни. Теперь всё безопасно управляется компилятором. |
| 5 | **Singleton, без которого можно обойтись** | Глобальная константа `LOG_LINE_PARSER` и `OnceLock` удалены. Парсеры легковесны и создаются на лету через `<LogLine as Parsable>::parser()`. |
| 6 | **Излишняя валидация вместо tight-типов** | Вместо ручной проверки `if value == 0` теперь используются `std::num::NonZeroU32` и `std::num::NonZeroI32`, что гарантирует корректность на уровне системы типов. |
| 7 | **Дублирование кода вместо дженериков** | 6 отдельных функций `just_parse_*` заменены на одну универсальную дженерик-функцию `pub fn just_parse<T: Parsable>`. |
| 8 | **Трейт-объекты там, где можно обойтись дженериками** | `Box<dyn MyReader>` заменён на дженерик `R: std::io::Read`. |
| 9 | **Последовательность `if` вместо одного `match`** | Введён `enum ReadMode { All, Errors, Exchanges }` с исчерпывающим сопоставлением, что исключает необходимость в `panic!` для неизвестных режимов. |
| 10 | **Enum, один из вариантов которого занимает несколько килобайт стека** | `AuthData` теперь хранит данные в куче: `pub struct AuthData(pub Box<[u8; 1024]>)`. |
| 11 | **Паника вместо возврата ошибки** | Библиотечный код больше не вызывает `panic!`. Ошибки парсинга отдельных строк корректно пропускаются, а ошибки ввода-вывода пробрасываются через `Result`. |

## Исправления логики (Bug Fixes)

Помимо рефакторинга, были исправлены логические ошибки оригинального кода:

### 1. Преждевременное завершение итератора
**Проблема:** В оригинальном `Iterator::next` использовалась конструкция `self.lines.next()?.ok()?`. Это означало, что при встрече первой же невалидной строки парсинг всего потока молча прекращался.

**Решение:** Итератор теперь использует `match` по результату парсинга, при ошибке (`Err(())`) делает `continue`, пропуская битую строку, но продолжая читать файл.

### 2. Обработка опечаток в реальных логах
**Проблема:** В реальных данных (`example.log`) встречались опечатки, не учтённые в строгой грамматике:
- `authrized_capital` вместо `authorized_capital`
- `request_id` вместо `requestid`

**Решение:** В парсер `AppLogJournalKind::CreateUser` и `LogLine` добавлен комбинатор `alt2`, который принимает оба варианта написания.

### 3. Корректная работа `do_unquote` с вложенными кавычками
**Проблема:** Строки вида `"CreateUser{ "user_id ": 10 } "` содержали неэкранированные кавычки внутри. Оригинальный парсер останавливался на первой встречной кавычке, ломая парсинг всей строки.

**Решение:** Логика `do_unquote` была доработана: она ищет закрывающую кавычку, проверяя баланс скобок `{` / `}` и `[` / `]` перед ней, а также допустимость символа, следующего за кавычкой (пробел, запятая, `}`, `]`, `:`).

### 4. Обработка пробелов внутри ключей
**Проблема:** В логах встречались пробелы внутри ключей в кавычках (например, `"user_id "` вместо `"user_id"`).

**Решение:** Парсер `QuotedTag` обрезает пробелы из содержимого кавычек перед сравнением с тегом.

### 5. Исправление бага в `AppLogJournalKind::WithdrawCash`
**Проблема:** В оригинальном коде вариант `WithdrawCash` ошибочно вызывал `DepositCash`.

**Решение:** Исправлено на `AppLogJournalKind::WithdrawCash`.

## Подавления Clippy

В начало файлов `lib.rs` и `parse.rs` добавлены атрибуты `#![allow(...)]`:

```rust
#![allow(clippy::result_unit_err)]
#![allow(clippy::type_complexity)]
#![allow(clippy::too_many_arguments)]
```

**Почему принято решение**
- **`result_unit_err`**: Возврат `Result<..., ()>` является стандартной практикой для парсер-комбинаторов (аналогично крейту `nom`), где важен только факт успеха/неудачи.
- **`type_complexity` и `too_many_arguments`**: Комбинаторы (`Alt`, `All`, `Permutation`) по своей природе генерируют вложенные типы и требуют много дженерик-параметров. Попытка "упростить" их через `type` алиасы ухудшит читаемость.

## Как собрать и проверить

Убедитесь, что вы находитесь в корне проекта.

### 1. Сборка проекта
```bash
cargo build
```

### 2. Запуск всех тестов
```bash
cargo test -- --nocapture
```
*Ожидаемый результат:* Все 16 тестов проходят. Вывод покажет успешный парсинг строк из `SOURCE`.

### 3. Запуск бинарного файла на реальном логе
```bash
cargo run -- example.log
```
*Ожидаемый результат:* Программа успешно откроет файл, распарсит все валидные строки и выведет их в консоль.

### 4. Проверка стиля и линтера
```bash
cargo fmt
cargo clippy --all-targets -- -D warnings
```
*Ожидаемый результат:* Команды завершаются без ошибок и предупреждений.

## Резюме

В проекте сделаны следующие исправления:
- Убраны `unsafe`, `Rc<RefCell>`, паники
- Используются tight-типы, дженерики, `match` вместо `if`
- zero-copy парсинг через `&str`, `Box` для больших данных в enum

Все тесты проходят, поведение на реальных данных (`example.log`) корректно и устойчиво к мелким нестыковкам в формате логов.
